# 3. 🎚️ O papel do parâmetro de regularização $\lambda$

A função objetivo é:

$$J(\theta, \theta_0) =\frac{1}{n}\sum_{i=1}^n \max(0, 1 - y^{(i)}(\theta \cdot x^{(i)} + \theta_0))+ \lambda \frac{1}{2}\|\theta\|^2$$



Interpretação:

- **perda média hinge** → quer classificar corretamente  
- **regularização** → quer margem grande  

$\lambda$ controla o equilíbrio:

- $\lambda$ grande → forte regularização → margem grande  
- $\lambda$ pequeno → fraca regularização → modelo flexível


> - Quanto maior o valor de $\lambda$ mais tentamos empurrar os limites de margem para longe

---

# 4. 🔄 Como a solução muda quando variamos $\lambda$

A lecture mostra isso visualmente:

### $\lambda$ pequeno  
- modelo tenta classificar tudo  
- fronteira se aproxima dos pontos  
- margem encolhe  
- risco de overfitting  

### $\lambda$ grande  
- modelo aceita erros para aumentar a margem  
- fronteira se desloca  
- limites de margem se afastam  
- solução passa a ser guiada pelos pontos mais distantes

# 5. 📉 Perda de treinamento vs perda de teste

A lecture introduz a curva clássica:

- **perda de treinamento** → sempre diminui quando aumentamos $C$  
- **perda de teste** → tem formato de U  

Por quê?

- modelos simples → subajuste (underfitting)  
- modelos complexos → sobreajuste (overfitting)  

---

# 6. 🔁 O parâmetro $C = 1/\lambda$

A lecture reescreve a função objetivo usando:

$$C = \frac{1}{\lambda}$$

Interpretando:

- $C$ grande → enfatiza a perda → modelo complexo | Overfitting  
- $C$ pequeno → enfatiza a regularização → modelo simples | Underfitting  

Esse é o parâmetro usado em implementações reais de SVM.

---

# 7. ⚖️ Underfitting vs Overfitting

### Underfitting (C pequeno)
- modelo simples  
- margem grande  
- erro de treino alto  
- erro de teste alto  

### Overfitting (C grande)
- modelo complexo  
- margem pequena  
- erro de treino baixo  
- erro de teste alto  

> Existe um $C^*$ ótimo que minimiza o erro de teste.

---

# 8. 🧪 Validação e escolha de $C^*$

Processo:

1. Divida o conjunto de treino em:
   - treino reduzido  
   - validação  

2. Para cada valor de $C$:
   - treine no conjunto reduzido  
   - avalie no conjunto de validação  

3. Escolha o $C^*$ que minimiza o erro de validação  

Isso é **validação cruzada** na prática.

<u> Observações: </u>

| Situação | Diagnóstico |
| --- | --- |
| Treino ↓, Validação ↑ |$\to\quad$ **Overfitting** |
| Treino ↑, Validação ↑ |$\to\quad$ **Underfitting** |

<br>

- Perda no treinamento baixa e  
   Perda na validação alta
   - overfitting
      - Aprendeu demais os dados do treino
      - Capturou ruído, padróes específicos, detalhes irrelevantes
      - Não generaliza para dados novos
- Perda no treinamento alta e  
   perda na validação alta
   - Underfitting
      - Nâo aprendeu o treino
      - A fronteira esta errada, simples demais, mal ajustada
      - Pode ser modelo fraco, poucos parâmetros, $\lambda$ muito alto, geatures ruis

```
                     ERRO (LOSS)
                     ↑
                     |
     UNDERFITTING    |        BOM AJUSTE          |      OVERFITTING
                     |
 Treino: alto        |   Treino: baixo            |   Treino: muito baixo
 Validação: alto     |   Validação: baixo         |   Validação: alto
                     |
                     |
   ┌──────────────┐  |   ┌──────────────┐        |   ┌──────────────┐
   │              │  |   │              │        |   │              │
   │   Modelo     │  |   │   Modelo     │        |   │   Modelo     │
   │   simples    │  |   │   adequado   │        |   │   complexo   │
   │   (fraco)    │  |   │   (bom)      │        |   │   demais     │
   └──────────────┘  |   └──────────────┘        |   └──────────────┘
                     |
                     +------------------------------------------------→ Complexidade
```

# 9. ⛰️ Gradiente Descendente

> Vamos agora falar de **otimização de algoritimos** para encontrar a solução das análises que fizemos até aqui

Atualização:
- Função multidimencional (semelhante a de 1 dimenção linear)
$$
\theta_j \leftarrow \theta_j - \eta \frac{\partial J}{\partial \theta_j}
$$


- Formato vetorial 
$$
\theta \leftarrow \theta - \eta \nabla_\theta J(\theta)
$$

Onde:

- $\eta$ = taxa de aprendizado  
- $\nabla J$ = gradiente  
- sendo que se $\theta = (\theta_1, \theta_2, ..., \theta_d)$, então:
$$\nabla_\theta J(\theta) = \left(\frac{\partial J}{\partial \theta_1}, \frac{\partial J}{\partial \theta_2}, \dots, \frac{\partial J}{\partial \theta_d} \right) \to \left(
\begin{matrix} \frac{\partial J}{\partial \theta_1} \\
\frac{\partial J}{\partial \theta_2} \\
\vdots \\
\frac{\partial J}{\partial \theta_d}
\end{matrix}\right) $$


Intuição:

- se a derivada é positiva → desça  
- se a derivada é negativa → suba  
- sempre mova na direção oposta ao gradiente 
- Para onde devo mover $\theta$ → para reduzir o erro mais rapidamente  

> - O gradiente aponta para a direção em que a função cresce mais rápido
>     - e sua magnitude diz: O quanto a função cresce se você andar nesta direção

### 🎯 Por que funciona mesmo sendo “ruidoso”?

Porque:
- cada exemplo puxa $\theta$ em uma direção
- mas **em média**, essas direções apontam para o mínimo
- se os passos forem pequenos, o ruído cancela
- e o movimento converge para o mínimo

### 🎯 Por que o gradiente é tão fundamental?

Porque ele é:
- a direção de maior aumento
- a melhor informação local possível
- a base da aproximação linear da função
- a chave para transformar uma soma em uma expectativa
- o que permite SGD, mini‑batch, Adam, RMSProp, etc.
- Sem gradiente, não existe aprendizado eficiente.

### 🧩 Resumo final (a definição que importa)

O gradiente é:
- um vetor
- que aponta para onde a função cresce mais rápido
- cuja magnitude diz o quanto ela cresce
- e que permite mover os parâmetros na direção oposta para minimizar a função
- podendo ser estimado por amostragem (SGD)

# 10. 🎲 Gradiente Descendente Estocástico (SGD)

A função objetivo é uma média:

$$ J(\theta) = \frac{1}{n}\sum_{i=1}^n J_i(\theta) $$

onde cada termo individual é:

$$ J_i(\theta) = \text{Loss}(y^{(i)},\, \theta^\top x^{(i)}) + \frac{\lambda}{2}\|\theta\|^2 $$



O truque é perceber que o termo de regularização não depende do exemplo, então podemos movê-lo para dentro da soma sem alterar o valor total. Assim, a função objetivo inteira pode ser vista como uma **média de funções objetivo mais simples**, cada uma associada a um único exemplo de treinamento.

Isso permite interpretar:
$$ J(\theta) = \mathbb{E}[J_i(\theta)] $$



Ou seja, a função objetivo é uma **expectativa** sobre os termos individuais.  
Se isso é verdade, então podemos estimar essa expectativa usando **amostragem**.

SGD faz exatamente isso:

- amostra um índice $i$
- calcula o gradiente apenas de $J_i(\theta)$
- atualiza os parâmetros usando esse gradiente parcial

Por quê?

- é muito mais rápido do que calcular a soma inteira
- funciona extremamente bem para datasets grandes
- cada atualização é barata e imediata

───────────────────────────────────────────────  
🎯 **A estocasticidade**
───────────────────────────────────────────────

A estocasticidade é o **ruído introduzido** quando substituímos o gradiente
verdadeiro:

$$\nabla J(\theta) = \frac{1}{n}\sum_i \nabla J_i(\theta)$$

por uma **amostra única**:

$$\nabla J(\theta) \approx \nabla J_i(\theta)$$




Cada exemplo puxa os parâmetros em uma direção diferente.
Isso faz o SGD “ziguezaguear” em vez de seguir uma linha suave.
Esse zigue-zague é exatamente a **estocasticidade**.

Formalmente, o ruído é:

$$\text{ruído} = \nabla J_i(\theta) - \nabla J(\theta)$$



───────────────────────────────────────────────  
🎯 **Por que a taxa de aprendizado precisa diminuir?**
───────────────────────────────────────────────

Como cada passo do SGD é ruidoso, se usarmos uma taxa de aprendizado constante,
o algoritmo nunca estabiliza — ele fica oscilando ao redor do mínimo.

Para garantir convergência, precisamos que:

- os passos sejam grandes o suficiente no início para avançar
- mas pequenos o suficiente no final para reduzir a variância do ruído

Por isso exigimos:

$$\sum_t \eta_t = \infty \quad\text{e}\quad \sum_t \eta_t^2 < \infty$$



Isso significa:

- a soma das taxas de aprendizado deve ser infinita  
  (para garantir progresso)
- mas a soma dos quadrados deve ser finita  
  (para controlar o ruído estocástico)

Assim, a taxa de aprendizado **deve diminuir ao longo das iterações**.

───────────────────────────────────────────────  
📌 **Resumo**  
───────────────────────────────────────────────

- A função objetivo é uma média de termos individuais.
- Cada termo pode ser usado isoladamente para atualizar os parâmetros.
- Isso introduz estocasticidade: o gradiente vira uma estimativa ruidosa.
- O ruído faz o SGD oscilar, mas também acelera o aprendizado.
- Para convergir, a taxa de aprendizado precisa diminuir ao longo do tempo.

# 11. 🧮 Atualização do SGD para perda hinge

Para um exemplo $(x_i, y_i)$:

### Se **não há perda**  
$$y_i(\theta \cdot x_i + \theta_0) \ge 1$$

- gradiente da hinge = 0  
- mas regularização ainda atua  

### Se **há perda**  

$$y_i(\theta \cdot x_i + \theta_0) < 1$$

- gradiente =
$$-y_i x_i$$

Atualização completa:

$$
\theta \leftarrow \theta - \eta_t \left(
\lambda \theta - y_i x_i \cdot \mathbf{1}[y_i(\theta \cdot x_i + \theta_0) < 1]
\right)
$$

# 12. 🔍 Diferenças entre Perceptron e SGD

| Aspecto | Perceptron | SGD (SVM) |
|--------|------------|-----------|
| Atualiza quando acerta? | Não | Sim (regularização) |
| Perda | 0/1 implícita | hinge |
| Margem | não controla | controla |
| Convergência | só se separável | sempre converge |
| Taxa de aprendizado | constante | decrescente |

# 13. 🧮 Caso realizável e programação quadrática

Se os dados são **linearmente separáveis** e não permitimos erros:

- queremos que todos os pontos satisfaçam

$$y_i(\theta \cdot x_i + \theta_0) \ge 1$$

- e queremos minimizar  

$$\frac{1}{2}\|\theta\|^2$$

Isso é um **programa quadrático**:

- objetivo quadrático  
- restrições lineares  

Pacotes como:

- CVXOPT  
- quadprog  
- libsvm  

resolvem isso diretamente.

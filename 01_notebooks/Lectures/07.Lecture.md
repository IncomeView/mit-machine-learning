=============================  
Lecture 7 — Parte 2  
User–Item Matrix e Representação do Problema
=============================

Sistemas de recomendação começam com uma estrutura fundamental:

> **A matriz usuário–item**, que registra preferências, ratings ou interações.

Nesta parte, vamos entender como essa matriz é construída, por que ela é esparsa,  
e como isso motiva o uso de modelos de fatores latentes.

------------------------------------------------------------
## 1. A matriz usuário–item

Considere:

- um conjunto de usuários $U = \{1, \dots, n\}$  
- um conjunto de itens $I = \{1, \dots, m\}$

Cada usuário $u$ pode fornecer um **rating** para um item $i$:

$$
r_{u,i} \in \mathbb{R}.
$$

Organizamos esses valores em uma matriz:

$$
R \in \mathbb{R}^{n \times m}.
$$

### Exemplo:

| Usuário / Item | Filme 1 | Filme 2 | Filme 3 |
|----------------|---------|---------|---------|
| Usuário A      | 5       | ?       | 3       |
| Usuário B      | ?       | 4       | ?       |
| Usuário C      | 2       | ?       | ?       |

Os “?” representam valores **não observados**.

------------------------------------------------------------
## 2. Esparsidade: o grande desafio

Na prática:

- cada usuário avalia poucos itens,  
- cada item recebe poucos ratings,  
- a matriz $R$ é **extremamente esparsa**.

Em plataformas reais:

- 99% dos valores são desconhecidos,  
- não podemos treinar modelos tradicionais diretamente,  
- precisamos prever valores ausentes.

O objetivo do sistema de recomendação é:

> **Prever os valores faltantes da matriz $R$.**

------------------------------------------------------------
## 3. O problema de predição

Queremos estimar:

$$
\hat{r}_{u,i}
$$

que representa a preferência prevista do usuário $u$ pelo item $i$.

Essas predições são usadas para:

- recomendar itens com maior $\hat{r}_{u,i}$,  
- ordenar listas de recomendação,  
- personalizar feeds,  
- sugerir produtos, filmes, músicas, etc.

------------------------------------------------------------
## 4. Abordagens para recomendação

Existem duas abordagens principais:

### 1. **Content-based filtering**  
Usa atributos dos itens e dos usuários.

Exemplos:

- gênero do filme,  
- idade do usuário,  
- palavras-chave,  
- categorias.

### 2. **Collaborative filtering**  
Usa apenas a matriz usuário–item.

Ideia central:

> Usuários semelhantes tendem a gostar de itens semelhantes.

A Lecture 7 foca na abordagem mais poderosa:

> **Collaborative filtering baseado em fatores latentes (Matrix Factorization).**

------------------------------------------------------------
## 5. Estrutura do problema

O sistema de recomendação deve:

1. **Representar usuários**  
2. **Representar itens**  
3. **Aprender padrões de preferência**  
4. **Generalizar para valores não observados**

A matriz $R$ contém:

- informação explícita (ratings),  
- informação implícita (interações),  
- padrões escondidos (fatores latentes).

------------------------------------------------------------
## 6. Motivação para fatores latentes

A matriz usuário–item pode ser explicada por:

- gostos dos usuários,  
- características dos itens,  
- relações não observáveis diretamente.

Exemplo:

- um usuário gosta de “ação” e “ficção científica”,  
- um filme tem “ação” e “ficção científica”,  
- o modelo deve capturar essa compatibilidade.

Mas esses atributos não são fornecidos explicitamente.

A solução é aprender **vetores latentes**:

- $p_u$ para cada usuário,  
- $q_i$ para cada item.

A predição será:

$$
\hat{r}_{u,i} = p_u \cdot q_i.
$$

Essa é a base da **Matrix Factorization**, que veremos na próxima parte.

------------------------------------------------------------
## 7. Conclusão da Parte 2

Nesta parte entendemos:

- o que é a matriz usuário–item,  
- por que ela é esparsa,  
- como isso define o problema de recomendação,  
- as abordagens content-based e collaborative filtering,  
- a motivação para fatores latentes.

=============================  
Lecture 7 — Parte 3  
Fatores Latentes e Matrix Factorization
=============================

Nesta parte, introduzimos o conceito central dos sistemas modernos de recomendação:

> **Representar usuários e itens como vetores em um espaço latente.**

Essa ideia permite prever ratings ausentes e capturar padrões complexos de preferência.

------------------------------------------------------------
## 1. Motivação: padrões escondidos na matriz usuário–item

A matriz $R$ contém:

- preferências explícitas (ratings),  
- preferências implícitas (interações),  
- padrões não observáveis diretamente.

Exemplo:

- Usuário A gosta de “ação” e “ficção científica”.  
- Filme X contém “ação” e “ficção científica”.  
- O sistema deve prever que A provavelmente gostará de X.

Mas:

- esses atributos não são fornecidos,  
- não sabemos quais “fatores” definem usuários e itens.

A solução é aprender **fatores latentes**.

------------------------------------------------------------
## 2. Representação latente de usuários e itens

Para cada usuário $u$, aprendemos um vetor latente:

$$
p_u \in \mathbb{R}^k
$$

Para cada item $i$, aprendemos um vetor latente:

$$
q_i \in \mathbb{R}^k
$$

Onde:

- $k$ é a dimensionalidade do espaço latente,  
- normalmente $k \ll n$ e $k \ll m$,  
- valores típicos: $k = 10, 20, 50, 100$.

### Interpretação

- $p_u$ representa os “gostos” do usuário.  
- $q_i$ representa as “características” do item.  
- Ambos são aprendidos automaticamente.

------------------------------------------------------------
## 3. Predição via produto interno

A predição do rating é:

$$
\hat{r}_{u,i} = p_u \cdot q_i.
$$

Ou seja:

- se o vetor do usuário aponta na mesma direção do vetor do item,  
- o produto interno é grande,  
- e o sistema prevê que o usuário gostará do item.

------------------------------------------------------------
## 4. Estrutura de baixo rank

A matriz $R$ é aproximada por:

$$
R \approx P Q^\top
$$

Onde:

- $P$ é a matriz $n \times k$ dos vetores de usuários,  
- $Q$ é a matriz $m \times k$ dos vetores de itens.

Isso significa que:

- $R$ é aproximada por uma matriz de **rank $k$**,  
- muito menor que $n$ ou $m$.

Essa é a ideia de **matrix factorization**.

------------------------------------------------------------
## 5. Função objetivo (erro quadrático)

Queremos encontrar $P$ e $Q$ que minimizem:

$$
\sum_{(u,i) \in \Omega} (r_{u,i} - p_u \cdot q_i)^2
$$

Onde:

- $\Omega$ é o conjunto de pares $(u,i)$ com rating observado.

### Observações

- Não tentamos ajustar valores ausentes.  
- Apenas ajustamos valores conhecidos.  
- O modelo generaliza para valores não observados.

------------------------------------------------------------
## 6. Regularização

Para evitar overfitting, adicionamos regularização:

$$
\sum_{(u,i) \in \Omega} (r_{u,i} - p_u \cdot q_i)^2
+ \lambda (\|p_u\|^2 + \|q_i\|^2)
$$

Onde:

- $\lambda > 0$ controla a força da regularização,  
- penaliza vetores latentes muito grandes,  
- melhora generalização.

------------------------------------------------------------
## 7. Intuição geométrica

Imagine:

- usuários como pontos em um espaço $k$-dimensional,  
- itens como pontos no mesmo espaço.

A predição é:

- alta quando os pontos estão próximos,  
- baixa quando estão distantes.

O sistema aprende automaticamente:

- clusters de usuários,  
- clusters de itens,  
- direções que representam “gostos” e “características”.

------------------------------------------------------------
## 8. Por que matrix factorization funciona tão bem?

1. **Captura padrões complexos**  
   - gostos não são lineares,  
   - fatores latentes capturam relações profundas.

2. **Escala para milhões de usuários e itens**  
   - $k$ é pequeno,  
   - atualizações são locais.

3. **Generaliza bem**  
   - regularização controla complexidade.

4. **Funciona com dados esparsos**  
   - não precisa de atributos explícitos.

------------------------------------------------------------
## 9. Conclusão da Parte 3

Nesta parte entendemos:

- como representar usuários e itens como vetores latentes,  
- como prever ratings via produto interno,  
- como aproximar a matriz usuário–item por uma matriz de baixo rank,  
- como formular o objetivo quadrático com regularização,  
- por que matrix factorization é tão poderoso.

=============================  
Lecture 7 — Parte 4  
SGD para Matrix Factorization
=============================

Nesta parte, veremos como **treinar** o modelo de fatores latentes usando  
**Stochastic Gradient Descent (SGD)** — o método mais simples, eficiente e amplamente utilizado  
em sistemas de recomendação reais.

------------------------------------------------------------
## 1. Relembrando o modelo

Cada usuário $u$ tem um vetor latente:

$$
p_u \in \mathbb{R}^k
$$

Cada item $i$ tem um vetor latente:

$$
q_i \in \mathbb{R}^k
$$

A predição do rating é:

$$
\hat{r}_{u,i} = p_u \cdot q_i.
$$

------------------------------------------------------------
## 2. Função objetivo com regularização

Queremos minimizar:

$$
\sum_{(u,i) \in \Omega} (r_{u,i} - p_u \cdot q_i)^2
+ \lambda (\|p_u\|^2 + \|q_i\|^2)
$$

Onde:

- $\Omega$ é o conjunto de ratings observados,  
- $\lambda$ controla a regularização.

------------------------------------------------------------
## 3. Erro do par usuário–item

Para cada par $(u,i)$ observado:

$$
e_{u,i} = r_{u,i} - p_u \cdot q_i.
$$

Esse erro é usado para atualizar os vetores latentes.

------------------------------------------------------------
## 4. Atualizações via SGD

SGD percorre apenas os pares observados $(u,i)$.

Para cada par:

1. Compute o erro:

   $$
   e_{u,i} = r_{u,i} - p_u \cdot q_i.
   $$

2. Atualize o vetor do usuário:

   $$
   p_u \leftarrow p_u + \eta (e_{u,i} q_i - \lambda p_u)
   $$

3. Atualize o vetor do item:

   $$
   q_i \leftarrow q_i + \eta (e_{u,i} p_u - \lambda q_i)
   $$

Onde:

- $\eta$ é a taxa de aprendizado,  
- $\lambda$ é a regularização.

### Intuição

- Se o usuário gostou mais do que o previsto, aumentamos a compatibilidade.  
- Se gostou menos, diminuímos.  
- A regularização evita que os vetores cresçam demais.

------------------------------------------------------------
## 5. Por que SGD funciona tão bem?

### • Escalabilidade

SGD atualiza apenas pares observados:

- não toca valores ausentes,  
- custo proporcional ao número de ratings,  
- funciona em bases gigantes (Netflix, Amazon, Spotify).

### • Simplicidade

As atualizações são locais:

- apenas $p_u$ e $q_i$ são modificados,  
- não há necessidade de manipular matrizes enormes.

### • Convergência rápida

Com taxa de aprendizado decrescente:

- o modelo converge para uma boa solução,  
- mesmo com milhões de usuários e itens.

------------------------------------------------------------
## 6. Inicialização dos vetores latentes

Normalmente:

- $p_u$ e $q_i$ são inicializados com valores pequenos aleatórios,  
- por exemplo, distribuição normal com média 0 e desvio padrão pequeno.

Isso evita simetrias e acelera a convergência.

------------------------------------------------------------
## 7. Ordem das atualizações

SGD pode:

- percorrer os pares $(u,i)$ em ordem aleatória,  
- embaralhar a cada época,  
- ou usar mini-batches.

A ordem aleatória geralmente melhora a convergência.

------------------------------------------------------------
## 8. Complexidade computacional

Para cada par $(u,i)$:

- custo é $O(k)$  
- atualizamos dois vetores de dimensão $k$

Se houver $|\Omega|$ ratings observados:

- custo total por época é $O(k |\Omega|)$

Isso escala muito bem.

------------------------------------------------------------
## 9. Conclusão da Parte 4

Nesta parte entendemos:

- como treinar matrix factorization via SGD,  
- como calcular o erro local,  
- como atualizar vetores de usuário e item,  
- como regularização controla complexidade,  
- por que SGD é eficiente e escalável.

=============================  
Lecture 7 — Parte 5  
Regularização, Sparsity e Cold Start
=============================

Nesta parte, discutimos três desafios fundamentais dos sistemas de recomendação:

1. **Regularização** — evitar overfitting nos vetores latentes.  
2. **Sparsity** — lidar com matrizes usuário–item extremamente esparsas.  
3. **Cold Start** — recomendar itens ou usuários novos sem histórico.

Esses problemas aparecem em qualquer sistema real, desde Netflix até Amazon.

------------------------------------------------------------
## 1. Regularização: controlando a complexidade dos vetores latentes

O modelo de matrix factorization tenta ajustar:

$$
r_{u,i} \approx p_u \cdot q_i.
$$

Mas se deixarmos $p_u$ e $q_i$ crescerem sem controle:

- o modelo memoriza os dados,  
- perde capacidade de generalização,  
- recomenda mal para itens não vistos.

A solução é adicionar regularização:

$$
\sum_{(u,i)\in\Omega} (r_{u,i} - p_u \cdot q_i)^2
+ \lambda (\|p_u\|^2 + \|q_i\|^2)
$$

### Intuição

- penalizamos vetores latentes grandes,  
- incentivamos soluções mais simples,  
- reduzimos variância,  
- melhoramos generalização.

### Efeito prático

- evita explosão dos vetores,  
- estabiliza o treinamento,  
- melhora recomendações para itens novos.

------------------------------------------------------------
## 2. Sparsity: o problema central dos sistemas de recomendação

A matriz usuário–item é **extremamente esparsa**:

- cada usuário avalia poucos itens,  
- cada item recebe poucos ratings,  
- 99% dos valores são desconhecidos em bases reais.

Isso cria desafios:

### • Dificuldade de aprendizado

Poucos dados por usuário → difícil aprender $p_u$.  
Poucos dados por item → difícil aprender $q_i$.

### • Risco de overfitting

Com poucos ratings, o modelo pode:

- ajustar demais os poucos dados disponíveis,  
- criar vetores latentes não representativos.

### • Solução: regularização + SGD

SGD atualiza apenas pares observados:

- não tenta ajustar valores ausentes,  
- aprende padrões globais a partir de poucos dados,  
- regularização evita overfitting.

------------------------------------------------------------
## 3. Cold Start: usuários e itens novos

O problema de cold start ocorre quando:

- um **usuário novo** entra no sistema,  
- um **item novo** é adicionado ao catálogo.

Como prever $\hat{r}_{u,i}$ se:

- o usuário não tem histórico,  
- o item não tem ratings?

### 1. Cold start de usuário

Sem histórico, não podemos aprender $p_u$.

Soluções:

- pedir alguns ratings iniciais,  
- usar dados demográficos,  
- usar conteúdo (content-based),  
- usar interações implícitas (cliques, tempo de visualização).

### 2. Cold start de item

Sem ratings, não podemos aprender $q_i$.

Soluções:

- usar metadados do item (gênero, categoria, descrição),  
- usar embeddings de conteúdo,  
- usar modelos híbridos (content + collaborative).

### 3. Cold start híbrido

Quando ambos são novos:

- usar modelos baseados em conteúdo,  
- usar similaridade com itens/usuários conhecidos,  
- usar aprendizado ativo (pedir avaliações iniciais).

------------------------------------------------------------
## 4. Estratégias práticas para sparsity e cold start

### • Regularização forte para usuários com poucos dados  
Evita vetores latentes instáveis.

### • Inicialização cuidadosa  
Vetores pequenos e aleatórios ajudam na convergência.

### • Modelos híbridos  
Combinam:

- conteúdo,  
- histórico,  
- embeddings,  
- filtragem colaborativa.

### • Coleta ativa de dados  
Pedir ao usuário:

- “Avalie 5 itens para melhorar suas recomendações.”

### • Uso de interações implícitas  
Mesmo sem ratings explícitos, podemos usar:

- cliques,  
- tempo de visualização,  
- compras,  
- favoritos.

------------------------------------------------------------
## 5. Conclusão da Parte 5

Nesta parte entendemos:

- como regularização controla a complexidade dos vetores latentes,  
- como sparsity afeta o aprendizado,  
- como cold start dificulta recomendações para novos usuários e itens,  
- como estratégias híbridas e dados implícitos ajudam a resolver esses problemas.

$$

$$

a preferência do usuário $u$ pelo item $i$.

A matriz usuário–item é extremamente esparsa:

- poucos dados por item,  
- risco de overfitting.

Soluções:

- regularização,  
- SGD,  
- modelos híbridos,

## 7. Cold Start
